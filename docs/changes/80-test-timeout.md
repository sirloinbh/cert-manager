# #80 프론트엔드 테스트의 시간 제한을 15초로 올림

이슈: [#80](https://github.com/sirloinbh/cert-manager/issues/80)

## 목적

같은 PC에서 다른 작업이 돌면 프론트엔드 테스트가 코드와 상관없이 5초 제한에 걸려 `npm run check`가 실패했다. [#54](54-study-plan-test-timeout.md)는 가장 느린 테스트를 나눴지만, 부하를 더 걸어 보니 여러 파일에서 실패해 테스트를 나누는 방법으로는 해결되지 않았다.

## 측정

프론트엔드 테스트만, CPU 코어 12개인 PC에 바쁜 프로세스 24개를 띄우고 돌렸다.

| 제한 | 실행 |      실패 | 가장 느린 테스트 |
| ---- | ---: | --------: | ---------------: |
| 5초  |  3회 | 회당 9~18 |          10~13초 |
| 15초 |  3회 |       0개 |  최대 약 14.45초 |

## 변경 내용

- 2026-11-01 사용자가 15초로 정했다. #54의 "제한을 늘리지 않음"을 바꾸는 결정이다.
- `frontend/vitest.config.ts`는 중앙 관리 파일이라 [project-standards#390](https://github.com/sirloinbh/project-standards/issues/390)에서 중앙 템플릿을 고쳤고, 동기화 PR #83으로 이 리포에 들어왔다. #83은 사용자가 병합했다.
- 이 PR은 기록과 다음 작업 문서만 고친다. 다음 작업 문서에 남아 있던 PR #15와 zod 설명은 지금 상태로 고치고, `npm audit` 결과를 적었다.

## 검증

#83이 병합된 main(`f2c9ec3`)에서 실행했다. 부하를 걸지 않은 상태다.

- `npm run check`: 통과. 백엔드 116개 통과, 프론트엔드 239개 통과·2개 건너뜀, 스킬 4개 통과.
- 문서만 고치므로 앱 테스트를 추가하지 않았다.

## 제한·후속 작업

- 15초 측정 때는 측정 스크립트가 정리하지 못한 프로세스 때문에 부하가 24개보다 컸고, 첫 실행의 시간 기록이 이상했다. 그래서 위 표의 15초 줄은 부하를 똑같이 맞춘 비교가 아니다.
- 그 부하에서 가장 느린 테스트가 15초에 가까웠다. 더 큰 부하에서는 다시 실패할 수 있다.
- 다른 앱은 측정하지 않았다. 중앙 템플릿을 쓰는 앱에는 같은 값이 들어간다.
