# #73 백엔드 검증 코드를 zod 4 문법으로 옮기기

- 이슈: [#73](https://github.com/sirloinbh/cert-manager/issues/73)
- 브랜치: `chore/73-zod4-syntax`

## 목적

중앙 `sirloinbh/project-standards#386`의 1단계다. 중앙이 `zod`를 4.6.7로 올릴 때 이 앱이 깨지지 않도록 코드를 먼저 옮긴다. 보안 권고 GHSA-mrhx-c7xc-m3w5의 Dependabot 알림은 그 동기화로 닫힌다. 이 PR만으로는 닫히지 않는다.

## 변경 — 2026-11-01

- `backend/src`의 zod 파일 10개(main에서 온 `daily-words.ts` 포함)가 `zod/v4`에서 불러온다. 설치된 3.25.76에 이 경로가 들어 있어 설치와 잠금 파일은 바꾸지 않았다.
- 스키마의 `message` 옵션을 `error`로 옮겼다. `ctx.addIssue`의 `message`는 zod 4에서도 그대로 쓴다.
- 화면에 보이는 문자열 길이 검사(`.min`, `.max`)를 `.refine`으로 옮겼다. zod 4는 타입 검사가 실패해도 길이가 있는 값에 `.min`, `.max`를 실행해, 문자열 자리에 배열을 보내면 같은 메시지가 두 번 나온다. 숫자 범위, 배열 길이, 스크립트 파일 스키마의 `.min`, `.max`는 그대로 두었다.
- `.partial()`, `.merge()`, `.default().optional()`, `z.record`는 이 앱에 없다. `.default()`는 모두 변환 없는 값이라 뒤에 건너뛰는 검증이 없다.
- `docs/next-steps/README.md`의 zod 3 유지 안내를 2026-11-01 결정에 맞게 고쳤다.

## 바뀌는 응답

전환 전후 스키마에 같은 입력 약 67만 건을 넣어 비교했다(필드 하나와 둘을 바꾼 조합, `constructor` 키가 있는 입력 포함). 유효한 입력의 결과는 모두 같고, 잘못된 입력이 통과하는 경우는 없다. 화면 입력에서는 이미 400인 입력의 메시지 구성만 바뀐다. 아래 표처럼 빠지는 메시지도, 새로 붙거나 바뀌는 메시지도 있다.

| 입력                                                        | 전                                     | 후                   |
| ----------------------------------------------------------- | -------------------------------------- | -------------------- |
| 음수 소수 점수 (`-1.5`)                                     | 정수여야 + 0 이상이어야                | 정수여야             |
| 소수 점수와 다른 필드 규칙 위반 (`score: 1.5`, 결과 전)     | 정수여야 + 결과 전에는 비워 주세요     | 정수여야             |
| 안전 범위를 넘는 정수 (`1e20`)                              | 이하여야                               | 정수여야 + 이하여야  |
| JSON `1e999` (무한대)                                       | 정수여야 + 이하여야                    | 숫자여야             |
| 시험일보다 앞선 형식 오류 만료일 (3.25.76에서만, 아래 참고) | 실제 날짜가 아닙니다 + 시험일 이후여야 | 실제 날짜가 아닙니다 |

스크립트에서는 응답이 아니라 판정이 세 가지 달라진다.

- LRCLIB 응답의 숫자가 무한대면 잘못된 응답으로 처리한다.
- 번역 파일의 `lineNumber`가 안전 범위를 넘으면 "원문이 DB와 다릅니다" 대신 "파일 형식이 내보낸 형식과 다릅니다"로 거절한다.
- 단어 파일이 1000개를 넘고 잘못된 항목도 있으면 거절 이유의 경로가 `words`에서 그 항목으로 바뀐다.

표의 만료일 행과 단어 파일 경로는 3.25.76의 `zod/v4`에서만 그렇다. 4.6.7에서는 전환 전과 같아진다. 나머지 변화는 4.6.7에서도 같다.

## 검증

- 처음 올릴 때 `npm run check`: 통과. `TEST_DATABASE_URL`을 비워 DB 통합 테스트는 제외했다.
- 새 테스트: 메시지 전체 비교(`backend/test/exam-attempts.test.ts`), 배열을 문자열 자리에 보낸 경우(`backend/test/certifications.test.ts`), 파일 스키마의 배열 길이 제한(`backend/test/array-limits.test.ts`).
- 4.6.7 전체 동작은 중앙 동기화 PR의 CI로 최종 확인한다.

## 리뷰와 병합 준비 — 2026-11-01

사용자가 병합을 승인했다. 브랜치가 오래되어 최신 main을 병합했고(충돌 없음, main의 새 코드도 이미 `zod/v4`) 독립 읽기 전용 리뷰 1회를 받았다.

- **리뷰 방식:** 전환 전, 현재, 현재 + 4.6.7을 가짜 DB로 띄워 같은 41,180건을 비교했다. 상태 코드와 DB로 가는 값은 모두 같고 5xx는 0건이다. 메시지 차이는 400 안에서만 난다. 4.6.7 패키지는 임시 폴더에만 풀었고 이 리포의 설치와 잠금 파일은 바꾸지 않았다.
- **중간 1건(반영):** 4.6.7에서 실패하는 테스트 입력을 두 버전이 같은 결과를 내는 입력으로 바꿨다.
- **낮음(반영):** 이 문서의 파일 수, 메시지 변화 설명, 3.25.76 한정 동작을 고쳤다. 배열을 제목·가사·번역 자리에 보내는 테스트를 추가했다.
- **낮음(반영 안 함):** 최대 길이 경계값과 `lyrics-fetch.ts`의 `.max(1000)` 테스트는 없다. 현재 동작은 맞다. `1e20`에 "정수여야"가 붙는 것은 화면에서 나오기 어려워 표에만 남긴다.
- **최종 검증:** `TEST_DATABASE_URL`을 `cert_test`로 지정해 `npm run check`를 실행했다. 백엔드 116개 모두 통과, 스킬 4개 통과. 프론트엔드는 238개 중 235개 통과, 2개 건너뜀, 1개 실패다. 실패한 `study-plan.test.tsx`의 테스트는 5초 시간 초과이고, 이 브랜치는 프론트엔드를 바꾸지 않았다(`git diff origin/main...HEAD -- frontend` 비어 있음). 같은 코드의 3회 실행 중 2회 실패, 1회 통과했다. [#80](https://github.com/sirloinbh/cert-manager/issues/80)에서 따로 고친다. `npm run knip`, `.standards/check.mjs`, `.standards/secret-scan.mjs`는 통과했다.
