# #70 단어 뜻·예문·어원 채우기

- 이슈: [#70](https://github.com/sirloinbh/cert-manager/issues/70)
- 브랜치: `docs/70-word-fill-record`

## 목적

단어장 2,809단어의 한국어 뜻, 예문, 어원 요소를 채운다. 채운 값은 이 PC의 `cert` DB와 `.local/`에만 있고 리포에는 넣지 않는다. 이 문서는 과정과 결과만 기록한다.

## 결과 — 2026-11-01

| 항목                     |    값 |
| ------------------------ | ----: |
| 전체 단어                | 2,809 |
| 뜻·품사·예문이 있는 단어 | 2,809 |
| 어원 요소가 있는 단어    | 1,107 |
| 서로 다른 어원 요소      | 1,168 |
| 어원 자료 없음           |     7 |

어원 자료가 없는 7단어(favorite, labor, neighbor, portion, exam, humor, catalog)에는 어원 요소가 없다. 모든 단어가 화면에 "AI 정리"로 표시된다.

## 진행 방법

1. 1~50위 샘플을 채웠고 사용자가 품질을 승인했다.
2. 나머지를 190~200단어 묶음으로 나눠 별도 에이전트가 채웠다. 어원 원문은 첫 항목의 앞 450자만 건넸다.
3. 결과를 스크립트로 검사하고, 근거가 약한 어원 요소를 지운 뒤 `npm run words:fill -w backend`로 넣었다.

## 어원 요소 판단

원문이 그 단어나 직접 어원을 나눈 경우만 넣었다. 다음은 넣지 않았다.

- 재구형(`*`)의 분해, "perhaps"처럼 추정으로 적힌 분해, 잘린 분해, 요소가 하나뿐인 분해
- 첫 1,000단어 검토에서 빼기로 한 here, through, hear, either 등과 뒤 묶음의 video, tool, phase 등 모두 30단어. 첫 1,000단어를 채울 때는 규칙이 더 느슨해 이 검토를 거쳤고, 뒤 묶음은 규칙을 좁혀 채웠다.

같은 이름의 요소는 먼저 저장된 뜻을 쓴다. 뜻이 다른 13개는 `suffix:s:plural`, `prefix:im:in`처럼 이름을 나눴다. 비슷한 뜻은 표현이 달라도 합쳤다.

## 검증

- DB 조회: 전체 2,809, 뜻 있음 2,809, 품사·예문 누락 0, 자료 없는 단어의 어원 요소 0.
- 파일 검사: 2,759단어 모두 입력과 순서가 같고, 필드 길이와 예문의 표제어 포함을 통과했다(`bound`처럼 변화형이 쓰인 예문 1건은 눈으로 확인).
- 내용 검사는 표본만 했다. 약 120단어의 뜻과 예문을 읽었고 문제를 찾지 못했다. 어원 요소는 형식과 근거 문구를 스크립트로 봤고, 2,050위까지의 목록 일부만 눈으로 훑었다. 마지막 759단어의 요소 목록은 읽지 않았다. 단어별로 원문과 대조하지는 않았다.

## 제한·후속 작업

- 뜻과 예문은 AI가 쓴 값이고, 샘플 승인은 앞 50단어로 받았다. 틀린 값이 남아 있을 수 있다.
- 어원 요소의 뜻풀이는 원문에 없는 경우 에이전트가 썼다. 같은 이유로 일부는 틀릴 수 있다.
- 다른 PC나 DB를 새로 만들면 `.local/word-batches/imported/`의 파일로 다시 넣어야 한다.
